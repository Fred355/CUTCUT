# CUTCUT 后续交付顺序

按 2026-11-11 最新需求，先完成编辑能力，再接 AI。本文是实施清单，不代表这些功能已经完成。

## 1. 持久化版本历史

已实现手动保存检查点、版本列表和恢复入口。恢复前保留当前未保存工作，版本放在工程内 `.cutcut-history`，使用内容哈希校验。重复内容不重复建快照。历史保留素材相对路径，因此不要手动删除 assets 文件；恢复不会回滚原始媒体字节。自动恢复草稿仍独立于版本历史。

已通过保存、迁移、重开、恢复前保留工作、篡改和路径穿越测试。桌面版本选择和旧工程回归待验收。

## 2. 转场、变速、关键帧

已查阅的上游候选：
- MLT：https://github.com/mltframework/mlt ，多媒体剪辑框架，核心 LGPL，具体模块需核对。
- libopenshot：https://github.com/OpenShot/libopenshot ，官方说明包括多层合成、动画曲线、时间映射、跨平台支持；LGPL-3.0-or-later。
- 当前 FFmpeg：已随应用打包，可以评估 xfade/acrossfade、setpts/atempo 和表达式滤镜，不必仅为效果替换完整编辑器。

接入前必须做同一小工程的 M1 Pro 预览/导出验证，并记录版本、原生依赖、许可证和打包方式。本轮选择继续使用已打包的 FFmpeg：预览在 Canvas/Web Audio 上执行共享参数，导出使用 setpts/atempo、alpha fade、scale/overlay 表达式，不额外安装 MLT 或 libopenshot。

首批效果边界：淡入淡出与交叉溶解；恒定正向 0.25–4 倍速且保音调；位置、缩放、透明度的线性和保持关键帧。增加工程格式迁移，不让旧版本静默丢失新效果。明确转场时长与源素材余量，变速后的音频、字幕、剪切点必须一致映射。关键帧使用片段局部帧。预览和导出使用同一计算规则。

## 3. AI 剪辑闭环与调度

1. AI 指令入口：自然语言要求、选中素材、时长、画布及允许修改的片段。
2. 素材分析：ASR、场景检测、代表帧视觉理解；以素材指纹和源时间段缓存。
3. Scene Memory：按场景保存摘要、时间范围、证据及模型版本，重新定位或修改源文件后使相关缓存失效。
4. Model Gateway：GPT/OpenAI、Claude、Gemini、DeepSeek 的能力适配、请求超时、有限重试、取消与统一用量。
5. Director Agent：根据用户目标、场景摘要和约束生成结构化剪辑方案。
6. AI Timeline Compiler：把经校验的方案编译到可编辑工程，检查引用、源范围、重叠和效果能力。
7. Edit Commands 与权限：模型只能提出白名单剪辑命令；主进程校验允许修改的片段 ID 和工程修订号。禁止模型执行 shell 或选择任意文件。指定范围外的轨道/片段保持不变。应用前展示变更，建立版本检查点，整批可撤销。
8. Task Orchestrator：把分析、归纳、规划及校验划分为可恢复任务，保持独立取消和有限调用上限。
9. 成本与质量路由：先筛选能力合格的模型，再按已配置价格和任务质量要求选择；校验失败才有限升级，不以价格覆盖功能要求。
10. Context Manager：切换模型携带结构化目标、时间码、决策和待办摘要；保留完整本地事件记录供追溯，不能丢弃修改权限或用户约束。
11. Usage Tracker：逐调用记录厂商、模型、输入/输出及缓存 token、价格版本和估算费用；无价格时显示未知。预算包括重试，调用前预留、调用后核对，超额停止后续任务；不把估算当成厂商账单。

上述任务系统尚未接通。当前只有请求适配、部分数据类型和时间线纯函数。制图 stable-diffusion.cpp、音乐 audio.cpp 排在剪辑闭环后，生成产物通过现有素材导入规则进入工程。
